MAVIS Operational Dashboard — пилот подтверждения предполагаемой даты закрытия.

Папку app из архива скопировать с заменой файлов в корень репозитория
mavisgroupiishki-alt/mavis-operational-dashboard, затем сделать commit.
Render использует автодеплой из main.

Затрагиваются ТОЛЬКО:
app/main.py
app/production_date_confirmation.py (новый)
app/static/app.js
app/static/production-date.html (новый)
app/static/production-date-journal.html (новый)

После деплоя запись ОТКЛЮЧЕНА по умолчанию. Это безопасный режим просмотра.
Включать PRODUCTION_DATE_CONFIRM_ENABLED=1 ТОЛЬКО после проверки входа
из локального приложения Bitrix24 и согласования тестовой сделки.

Эксперт: https://mavis-operational-dashboard.onrender.com/cabinet/production-date?deal_id=12345
Открывать внутри подтверждённой Bitrix-сессии, заменив 12345 на ID сделки.
Руководитель: https://mavis-operational-dashboard.onrender.com/production-date-journal
В дашборде раздел Производство появится ссылка «Журнал дат закрытия».

ОГРАНИЧЕНИЯ:
1. Обычное ручное перетаскивание сделок в Bitrix24 остаётся разрешено.
   Эта версия НЕ реализует строгий запрет прямых переходов.
2. Журнал фиксирует только смены стадии через новую форму.
   Полная история изменений из Bitrix и автоматические роботы НЕ отслеживаются.
3. Журнал хранится в существующем KV дашборда; при одновременных обновлениях
   из нескольких процессов возможны конфликты. Это пилот, не итоговый аудит.
4. Перед массовым внедрением нужно отдельно проверить доступ локального приложения,
   права экспертов, роботов на этапах, конфликты параллельных изменений и историю стадий.
5. Если старые файлы в GitHub менялись после исходного архива от 02.11.2026,
   сначала сравните версии. Не перезаписывайте более свежие изменения вслепую.
