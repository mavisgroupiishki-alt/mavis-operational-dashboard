# Технический план: Обсуждение, повторение и напоминания задач

**Спека:** [spec.md](spec.md)  **Создан:** 2026-09-25

## Технологии

Существующие FastAPI, браузерный JavaScript и `Storage` (Supabase KV с SQLite-зеркалом). Новые зависимости не нужны: повторение рассчитывается стандартными `datetime`/`calendar`.

## Архитектура

```
Диалог задачи
  ├─ комментарий ──> POST /api/key-tasks/{id}/comments ──> Storage task_comments:{id}
  ├─ изменение ───> PATCH /api/key-tasks/{id} ──────────> Storage + task_activity:{id}
  └─ открыть ─────> GET /api/key-tasks/{id}/activity ──> комментарии + история

Список задач ──> локально вычисляет просрочку ──> плашка + фильтр «Просроченные»
```

## Схема данных

- `manual_key_tasks`: расширить поле `recurrence` (`none`, `weekly`, `monthly`) и необязательный `recurrence_spawned_at`.
- `task_activity:{task_id}`: массив неизменяемых событий `{id, kind, text, author_profile_id, author_name, created_at}`.
- `task_comments:{task_id}`: массив неизменяемых комментариев `{id, text, author_profile_id, author_name, created_at}`.

## API / интерфейсы

- `GET /api/key-tasks/{task_id}/activity` — комментарии и история одной задачи.
- `POST /api/key-tasks/{task_id}/comments` — добавить комментарий выбранным профилем.
- `POST`/`PATCH /api/key-tasks` — принимают повторение и профиль автора изменения.
- Диалог задачи: выбор повторения, комментарии, хронология.
- Рабочее пространство: постоянное напоминание и фильтр просрочки.

## Зависимости

Сначала нормализация и сохранение полей задач, затем API событий, затем интерфейс и тесты.

## Риски

- Двойное сохранение статуса «Завершена» может создать клон дважды. Митигация: создавать экземпляр только при переходе в этот статус и хранить метку создания.
- Долгие ленты активности могут замедлять интерфейс. Митигация: загружать их только при открытии одной задачи и ограничить длину текста.
- Смена месяца для 29–31 числа. Митигация: ограничивать следующий день последним днём месяца.
