# Личные кабинеты ОП в Bitrix24

**Статус:** черновик для реализации
**Дата:** 2026-10-29
**Владелец:** MAVIS Group

## Цель

Открывать операционный кабинет из Bitrix24 и автоматически показывать сотруднику
только его рабочие сделки, дела и звонки. Руководитель видит сводку команды и
прослушку из Jarvis. Bitrix24 остаётся источником фактов; кабинет ничего в CRM
не создаёт и не изменяет.

## Пользователи и доступ

- Вход выполняется через локальное приложение Bitrix24. Сервер получает
  подтверждённый Bitrix user ID из серверной сессии, а не из query-параметра,
  localStorage или формы браузера.
- Сервер сверяет `APPLICATION_TOKEN` запуска с токеном установленного локального
  приложения, сохранённым только в серверной переменной окружения.
- Менеджер видит только сущности, за которые он назначен ответственным.
- Руководитель видит команду, исключения и записи звонков. Список руководителей
  задаётся отдельно по Bitrix user ID, а не по отображаемому имени.
- Старый парольный вход дашборда не расширяет права личного кабинета.
- Если Bitrix не подтвердил пользователя, данные не выдаются; интерфейс показывает
  понятный статус входа, а не чужую сводку.

## Менеджерский кабинет

### Вчерашний результат

- Количество звонков, успешные звонки длительностью от 60 секунд, дела и
  просроченные дела за вчера по часовому поясу дашборда.
- Норма успешных звонков: 50. Отображаются факт, остаток до нормы и список
  подтверждающих записей.
- Просроченные сделки, сделки без открытого дела и сделки, которые превышают
  срок нахождения на этапе. Каждый показатель раскрывается в список с прямой
  ссылкой на сущность Bitrix24.
- Время допустимого нахождения на этапе берётся только из согласованной карты
  SLA этапов/роботов Bitrix. Пока карта не подключена, блок явно говорит
  «SLA этапов не настроена» и не маркирует сделки как застрявшие.

### Качество CRM и возможности

- Отдельно показываются сделки без источника и без типа клиента. Статус
  «заполнено» определяется по фактическим полям сделки, а не по наличию текста
  в карточке.
- Для активных сделок проверяется наличие услуг ИСО и СУОТ среди товарных
  позиций. Если услуга отсутствует, кабинет показывает подсказку о допродаже
  только после проверки реестра. При недоступном реестре подсказка помечается
  как «нужна проверка реестра», а не как факт.

### Звонки и прослушка

- Менеджер видит только свои разборы и записи из Jarvis.
- Руководитель видит разборы команды и фильтр по сотруднику.
- В разборе отдельно фиксируются цитаты и тайм-коды для запрещённых формулировок:
  «Получится оплатить?», «Сможете оплатить?», «Как у вас с деньгами?».
- Проверяется применение согласованных триггеров: начало с пользы и оплаты,
  дефицит времени, конкретный срок оплаты, снятие барьера по договору,
  дублирование счёта в мессенджер, информирование о следующем шаге вместо
  вопроса-разрешения. Отсутствие данных не снижает оценку и не создаёт
  выдуманную ошибку.

## Кабинет руководителя

- Сводка команды по тем же метрикам с переходом к сотруднику и исходным
  сущностям Bitrix24.
- Прослушка Jarvis доступна только руководителям и не раскрывает записи
  неавторизованным пользователям.
- Списки исключений сортируются по просрочке и риску, а не по случайному
  порядку загрузки.

## Интеграции и ограничения

- Локальное приложение Bitrix24 передаёт краткоживущую авторизацию только на
  сервер. Ключи приложения, webhook и токены Jarvis не попадают в браузер,
  Git или логи.
- Сервер проверяет разрешённый портал Bitrix24 до обращения по полученному
  домену. Это исключает подмену URL запуска.
- Данные сделок и задач кэшируются коротко и привязаны к подтверждённому
  Bitrix user ID. Ответы одного сотрудника не используются для другого.
- Отсутствие Jarvis, реестра или карты SLA не блокирует основные данные:
  соответствующий блок показывает недоступность с возможностью повторить.

## Не входит в первый релиз

- Изменение роботов, стадий, задач, сделок или товарных позиций в Bitrix24.
- Автоматическое создание писем, задач или сообщений по результатам анализа.
- Присвоение SLA этапам без выгрузки существующих правил Bitrix24.
- Утверждение допродажи без ответа из реестра.

## Условия запуска

1. В Bitrix24 создаётся/устанавливается локальное приложение с URL запуска
   дашборда. Его `APPLICATION_TOKEN` сохраняется в
   `BITRIX_LOCAL_APPLICATION_TOKEN` только на сервере.
2. Назначаются Bitrix user ID руководителей.
3. Подключается карта SLA этапов из роботов и интерфейс реестра ИСО/СУОТ.
4. Jarvis предоставляет ограниченный по пользователю read-only API для списка
   разборов и защищённой прослушки.

## Критерии приёмки

1. Один и тот же URL кабинета, открытый менеджером и руководителем Bitrix24,
   выдаёт разные серверно-проверенные области данных.
2. Менеджер не может подменой ID, cookie или HTTP-параметра получить сделку,
   задачу либо запись другого сотрудника.
3. Успешный звонок учитывается только при длительности не менее 60 секунд;
   дневная норма равна 50.
4. Каждый показатель исключений раскрывается до списка исходных объектов.
5. При принудительной недоступности Jarvis, реестра или SLA основная страница
   остаётся рабочей и показывает точный источник ограничения.
6. Проверки запрещённых фраз содержат только подтверждённые цитаты и тайм-коды.
