# Технический план: Рабочий канбан проектов

**Спека:** `spec.md`  **Создан:** 2026-09-25

## Архитектура

`TASK_STATUSES` расширяется до восьми согласованных стадий. Бэклог хранится совместимо со старым булевым полем, но представляется стадией `backlog`. Карточка передаёт новую стадию через существующий PATCH задачи. Сохранённые виды хранятся отдельным ключом постоянного dashboard storage и применяются только к фильтрам текущего проекта.

## Компоненты

| Блок | Файлы | Проверка |
|---|---|---|
| Модель стадий и сохранённых видов | `app/key_tasks.py`, `app/storage.py`, `app/main.py` | unit/API tests |
| Канбан, DnD, быстрые виды | `app/static/app.js`, `app/static/index.html` | JS syntax, browser smoke-test |
| Контрастный проектный экран | `app/static/styles.css` | desktop/iPhone visual check |

## Риски

- HTML5 drag-and-drop не является удобным на touch-экранах; сохранён выбор стадии в форме задачи.
- Старые задачи с `backlog=true` нормализуются к стадии `backlog`, не теряя данные.
