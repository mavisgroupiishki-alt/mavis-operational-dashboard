# Технический план: отдельный доступ маркетолога

**Спека:** [spec.md](spec.md)  **Создан:** 2026-09-24

## Архитектура

`VIEW_PASSWORD` идентифицирует полный доступ, `MARKETER_PASSWORD` — ограниченный. Сервер подписывает роль в HttpOnly cookie с `DASHBOARD_SESSION_SECRET`. Middleware определяет роль для каждого запроса. Snapshot очищается для маркетолога до отправки; чувствительные маршруты отклоняются сервером. Frontend отображает очищенные значения как «—».

## API / интерфейсы

- `POST /login`: распознаёт полный или маркетинговый пароль.
- `GET /api/snapshot`, `GET /api/sales-section`: обезличенный ответ для маркетолога.
- `GET /api/marketing`: разрешён маркетологу.
- Детализации, AI, Jarvis, ключевые задачи, планы и записи: `403` для маркетолога.

## Риски

- При отсутствии обоих паролей существующий публичный режим нельзя считать защищённым.
- Для запуска нужны три значения в Render: полный пароль, пароль маркетолога и секрет сессии.

## Проверка конституции

- [ ] Доступ проверяется на сервере.
- [ ] Реальные значения не подменяются в полном доступе.
