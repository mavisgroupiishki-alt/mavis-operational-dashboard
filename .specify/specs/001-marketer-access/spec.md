# Спецификация: отдельный доступ маркетолога

**ID:** 001-marketer-access  **Статус:** Approved  **Создана:** 2026-09-24

## Цель

Дать одному маркетологу доступ ко всей навигации дашборда, сохранив реальные данные только в разделе «Маркетинг».

## Пользовательские истории

- Как маркетолог, я хочу видеть структуру всех разделов, чтобы понимать устройство операционного дашборда.
- Как маркетолог, я хочу видеть реальные показатели только маркетинга, чтобы работать со своим направлением.
- Как владелец дашборда, я хочу, чтобы маркетолог не мог получить реальные операционные данные через API, детализации или чат.

## Функциональные требования

1. Система ДОЛЖНА принимать отдельный пароль маркетолога и устанавливать серверную сессию роли «marketer».
2. Полный доступ ДОЛЖЕН сохраняться для существующего пароля владельца.
3. Для роли «marketer» все данные вне раздела «Маркетинг» ДОЛЖНЫ быть обезличены в ответах API.
4. Роль «marketer» НЕ ДОЛЖНА получать детализации сделок, планы, команды, ключевые задачи, операции Jarvis, CRM-аудит или ответы AI-чата.
5. Маркетинговый API ДОЛЖЕН оставаться доступным маркетологу с реальными значениями.
6. Все операции изменения данных ДОЛЖНЫ быть недоступны маркетологу.

## Вне скоупа

- Несколько маркетологов и персональные учётные записи.
- Изменение данных Bitrix24 из дашборда.

## Критерии приёмки

- [ ] Вход с паролем маркетолога создаёт ограниченную роль.
- [ ] Snapshot и тяжёлая детализация не отдают реальные не-маркетинговые числа и имена.
- [ ] API маркетинга доступен, запрещённые API возвращают 403.
- [ ] Полный вход сохраняет текущее поведение.
