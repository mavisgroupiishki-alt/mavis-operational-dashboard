# Спецификация: Быстрый старт операционного дашборда

**ID:** 002-fast-startup  **Статус:** Approved  **Создана:** 2026-09-11

## Цель

Показывать главный экран сразу после получения краткого snapshot и не строить тяжёлую аналитику продаж до открытия раздела «Продажи».

## Пользовательские истории

- Как руководитель, я хочу сразу видеть главный экран после открытия дашборда на телефоне.
- Как руководитель, я хочу получить детальную аналитику продаж при переходе в соответствующий раздел, не блокируя остальные контуры.

## Функциональные требования

1. Начальный API snapshot ДОЛЖЕН исключать глубокие вложенные разрезы продаж, сохраняя итоговые показатели и компактные строки менеджеров.
2. Дашборд ДОЛЖЕН загружать полный раздел продаж отдельным запросом только при его открытии.
3. Пока полная разбивка продаж загружается, экран ДОЛЖЕН показывать понятный статус без бесконечного спиннера.
4. Снимки, планы и состав команды ДОЛЖНЫ оставаться на подключённом диске `/var/data` между перезапусками Render.
5. Существующие API без параметра компактного режима ДОЛЖНЫ сохранять полный ответ.

## Вне скоупа

- Изменение расчётов продаж, производства или чистой выручки.
- Перенос данных в новый внешний сервис: persistent disk уже подключён к текущему сервису.

## Критерии приёмки

- [x] Компактный ответ не содержит вложенных разрезов менеджеров, источников и продуктов, но сохраняет нужные KPI.
- [x] Открытие главного экрана не рендерит тяжёлую страницу продаж.
- [x] Открытие «Продаж» получает полный набор данных и сохраняет существующие расшифровки.
- [x] Тесты проверяют компактный контракт и проходят вместе с прежним набором.
