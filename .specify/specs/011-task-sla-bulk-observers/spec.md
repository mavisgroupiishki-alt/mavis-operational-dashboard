# Спецификация: контроль задач по SLA, массовые действия и наблюдатели

**ID:** 011-task-sla-bulk-observers  **Статус:** Approved  **Создана:** 2026-09-29

## Цель

Помочь руководителю быстро видеть задачи, застрявшие на этапе, управлять группой задач за одно действие и подключать к контролю роли без назначения их исполнителями.

## Уточнения и принятые решения

- SLA задаётся в календарных днях для каждого общего этапа; по умолчанию для «На проверке» — 2 дня, для остальных этапов контроль выключен до настройки.
- Отсчёт начинается при фактическом переходе задачи в этап. Для старых задач без истории перехода используется время последнего изменения.
- Массовое действие не завершает задачи: завершение требует фактических часов на каждой задаче.
- Наблюдатель получает напоминания только внутри дашборда и не считается исполнителем или ответственным.

## Пользовательские истории

- Как руководитель, я хочу видеть задачи с нарушенным SLA этапа, чтобы вовремя разбирать зависания.
- Как руководитель, я хочу выбрать несколько задач и изменить им этап, срок, ответственного или добавить исполнителя, чтобы не повторять действие вручную.
- Как руководитель, я хочу добавить к задаче наблюдателей, чтобы нужные роли видели её напоминания без изменения загрузки.

## Функциональные требования

1. Каждый общий этап ДОЛЖЕН хранить необязательный SLA в днях; «На проверке» ДОЛЖЕН иметь стартовое значение 2 дня.
2. Система ДОЛЖНА сохранять момент последнего перехода задачи между этапами и показывать нарушение SLA в карточках, списке и напоминаниях.
3. Массовый режим ДОЛЖЕН позволять выбрать задачи текущего экрана и одним подтверждённым действием изменить им этап (кроме завершения), срок, ответственного и/или добавить исполнителя.
4. Массовое действие ДОЛЖНО валидировать роли, этапы и задачи до сохранения, не затрагивать архивные задачи и оставлять запись в истории каждой изменённой задачи.
5. У задачи ДОЛЖЕН быть список наблюдателей из активных ролей; эти роли ДОЛЖНЫ быть видны в карточке задачи и отдельном блоке «Мои уведомления» при выборе соответствующего рабочего профиля.
6. Наблюдатель ДОЛЖЕН получать внутри дашборда уведомления о просроченном сроке, сроке сегодня/скоро и нарушенном SLA, не добавляясь в загрузку исполнителей.

## Вне скоупа

- Внешние push-, email- или Bitrix-уведомления.
- Массовое завершение задач и ввод фактических часов одной цифрой для разных задач.
- Изменение задач Bitrix24.

## Критерии приёмки

- [x] Задача, остающаяся на «На проверке» дольше 2 календарных дней, визуально отмечается и появляется в блоке внимания.
- [x] Выбранные активные задачи можно разом переназначить, перевести в этап, назначить срок или дополнить исполнителем; каждая фиксирует историю изменения.
- [x] Наблюдатель видит связанные с задачей напоминания в дашборде, но не учитывается в нагрузке.
- [x] Настройки SLA, наблюдатели и время переходов переживают перезагрузку и публикацию.
