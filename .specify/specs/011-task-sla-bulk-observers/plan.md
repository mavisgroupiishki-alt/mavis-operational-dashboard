# Технический план: SLA, массовые действия и наблюдатели

**Спека:** [spec.md](spec.md)  **Создан:** 2026-09-29

## Архитектура

`task_workspace_statuses` получает `sla_days`; для задач хранятся `status_changed_at` и `watcher_ids`. Сборщик рабочего пространства рассчитывает возраст этапа, статус SLA и отдельные напоминания для активной роли-наблюдателя. Серверный endpoint массового действия валидирует весь набор перед изменением, применяет разрешённые поля к задачам дашборда и записывает историю. Клиент добавляет режим выбора, окно массового действия, выбор наблюдателей и конфигурацию SLA в существующем окне этапов.

## Риски

- Старые задачи не имеют времени входа в этап: используется существующее `updated_at` без выдачи ложной точности.
- Массовое завершение может обходить обязательные часы: завершающий этап исключён из массовой формы.
- Наблюдатели не должны появляться в расчёте загрузки: они существуют в отдельном поле и не входят в `executor_ids`.
