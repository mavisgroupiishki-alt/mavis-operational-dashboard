# Технический план: Исторические продажи июля и августа

## Подход

Сервер помечает только два согласованных месяца как `deal_amount` и не запускает для них фоновый запрос «Чистой выручки». Браузер использует уже существующие CRM-агрегаты `sales_amount` и `average_check`; для всех разрезов они построены из `OPPORTUNITY` успешных сделок.

## Изменения

1. В `app/main.py` добавить явный список исторических месяцев и контракт источника финансов.
2. В `app/static/app.js` переключить подписи, карточки, таблицы и финансовые пояснения на CRM-сумму сделок при этом контракте.
3. Добавить серверные и клиентские тесты перехода, не меняя стандартный контур сентября.

## Проверка конституции

- [x] Принцип I: источник для исторических месяцев явно указан как `OPPORTUNITY`, без имитации чистой выручки.
- [x] Принцип IV: отсутствующий исторический график платежей не показывается как ноль.
