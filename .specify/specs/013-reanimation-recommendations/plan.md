# Технический план: Реанимируем реанимацию

**Спека:** [spec.md](spec.md)
**Создан:** 2026-10-02

## Технологии

Jarvis (Flask, существующий Bitrix-клиент и сохранённые AI-анализы звонков) формирует компактный защищённый JSON. Операционный дашборд (FastAPI и vanilla JS) проксирует его на сервере и отображает очередь. Для явного действия дашборд вызывает отдельный защищённый маршрут Jarvis; только он выполняет строго ограниченный вызов Bitrix.

## Архитектура

```text
Bitrix: сделки «Реанимация» + дела + комментарии/поля
              │
              ▼
Jarvis: правила исключения + результаты AI-анализов последних звонков
              │ protected recommendation payload
              ▼
Dashboard: «Реанимируем реанимацию» + доказательства
              │ explicit confirmed click
              ▼
Jarvis validates current deal → Bitrix main sales / «Новая» → audit record
```

## Схема данных

В ответе очереди каждая строка содержит идентификатор сделки, её отображаемые поля, объяснение, использованный контекст и версию/время среза. Аудит действий сохраняется в отдельной таблице Jarvis при наличии базы данных; отказ не меняет CRM.

## API / интерфейсы

- `GET /api/integrations/operations/reactivation-recommendations` — защищённая выдача очереди Jarvis.
- `POST /api/integrations/operations/reactivation-recommendations/{deal_id}/reactivate` — защищённое явное перемещение после повторной валидации.
- `GET /api/reactivation-recommendations`, `POST /api/reactivation-recommendations/{deal_id}/reactivate` — серверные маршруты дашборда; секрет Jarvis не покидает сервер.

## Зависимости

Сначала создаётся безопасный сборщик рекомендаций Jarvis и его тесты, затем прокси и действие дашборда, затем UI. Действие зависит от динамического получения воронки «Реанимация» и стадии «Новая» из Bitrix.

## Риски

- В портале могут отличаться ID воронки и стадии. Митигация: находить по названию и отклонять действие при неоднозначности.
- Не все комментарии или звонки доступны. Митигация: обозначать отсутствующий источник, а не додумывать факт.
- Запросы истории CRM могут быть тяжёлыми. Митигация: ограничить сделки, события и текст контекста.

## Проверка конституции

- [x] Принцип I: рекомендации содержат первичные даты и ссылки, а не подменяют CRM-статус.
- [x] Принцип II: сканер остаётся read-only; единственное изменение — явное, авторизованное, проверяемое и журналируемое действие.
- [x] Принцип III: каждая рекомендация имеет причины и контекст.
- [x] Принцип IV: недоступный Jarvis показывается как недоступный.
