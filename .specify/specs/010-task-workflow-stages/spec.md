# Спецификация: общие этапы и поиск задач

**ID:** 010-task-workflow-stages  **Статус:** Approved  **Создана:** 2026-09-29

## Цель

Дать руководителю единый управляемый процесс задач во всех проектах и быстрый способ найти задачу по её содержанию.

## Пользовательские истории

- Как руководитель, я хочу создавать, переименовывать и безопасно удалять общие этапы, чтобы процесс соответствовал работе команды.
- Как руководитель, я хочу назначить автодействие этапа, чтобы задача на проверке попадала к ОП Директору без ручного переназначения.
- Как руководитель, я хочу искать задачи по названию и описанию в любом представлении, чтобы быстро находить нужную работу.

## Функциональные требования

1. Справочник этапов ДОЛЖЕН быть общим для всех проектов и сохраняться в постоянном хранилище.
2. «Бэклог» и завершающий этап ДОЛЖНЫ оставаться системными: их можно переименовать, но нельзя удалить.
3. При удалении пользовательского этапа система ДОЛЖНА требовать этап назначения и перенести туда все его задачи.
4. У этапа ДОЛЖНО быть необязательное автодействие назначения ответственного из активных ролей.
5. При реальном переходе на этап с автодействием задача ДОЛЖНА стать ответственной за выбранной ролью и сохранить прежних исполнителей.
6. Поиск ДОЛЖЕН учитывать название и описание задачи, не изменяя данные и фильтруя активное представление.

## Вне скоупа

- Автоматическое изменение задач в Bitrix24.
- Отдельные наборы этапов по проектам.
- Автоматическое закрепление задач.

## Критерии приёмки

- [ ] Новый этап виден в форме, фильтрах и канбане каждого проекта после обновления.
- [ ] Этап с задачами удаляется только вместе с явным переносом этих задач.
- [ ] Переход в «На проверке» с настроенным правилом назначает ОП Директора ответственным.
- [ ] Поиск находит совпадения из названия и описания на общем, проектном и ролевом экране.
