# Технический план: общие этапы и поиск задач

**Спека:** [spec.md](spec.md)  **Создан:** 2026-09-29

## Архитектура

`task_workspace_statuses` хранит нормализованный список этапов. Сервер отдаёт его с задачами, валидирует статусы и применяет автодействие перед сохранением задачи. Клиент открывает единое окно «Этапы» и локально фильтрует уже полученные задачи по названию и описанию.

## Риски

- Удаление этапа не должно терять задачи: обязательный этап-получатель и серверный перенос.
- Семантика бэклога и завершения должна сохраниться: системные идентификаторы не удаляются.
- PWA не должна отдать старый интерфейс: новая версия shell-кеша.

## Проверка конституции

- [x] Настройки этапов долговечны и не зависят от Bitrix24.
- [x] Автодействие меняет только задачи дашборда, не CRM.
- [x] Ошибка удаления или неактивная роль возвращается явно.
