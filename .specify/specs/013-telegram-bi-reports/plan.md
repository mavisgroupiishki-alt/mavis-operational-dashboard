# Технический план: Ежедневные отчёты Telegram из BI-конструктора

**Спека:** [spec.md](spec.md)  **Создан:** 2026-10-02

## Технологии

Python Playwright запускает Chromium на Render, входит в Bitrix24 и снимает только dashboard ID 80. `httpx` отправляет Telegram сообщения и фото. Существующий snapshot остаётся единственным источником числового текста.

## Архитектура

`Render secrets → BI renderer → проверка страницы → PNG → Telegram sender`

`операционный snapshot → строгое форматирование двух текстов → Telegram sender`

## API / Интерфейсы

- `POST /api/reports/test-send` — защищённая тестовая отправка в личный чат.
- Переменные: `BITRIX_BI_LOGIN`, `BITRIX_BI_PASSWORD`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_TEST_CHAT_ID`.

## Риски

- Bitrix может запросить 2FA или изменить форму входа; тогда отправка вернёт явную ошибку без подмены скрина.
- Chromium потребляет память; запускается только на запросе/расписании и всегда закрывается.
- Время расписания пока не определено, поэтому фоновой ежедневный запуск не включается.

## Проверка конституции

- [ ] Источники не смешиваются: изображение только BI, числа только operational snapshot.
- [ ] Интеграция read-only, секреты только в окружении Render.
- [ ] Ошибки BI не маскируются нулём либо иной картинкой.
