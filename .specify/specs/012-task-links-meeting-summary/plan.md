# Технический план: связи задач и итог встречи

**Спека:** [spec.md](spec.md)  **Создан:** 2026-09-30

## Архитектура

Поле `links` хранится рядом с остальными данными dashboard-owned задачи. `Storage` нормализует HTTP(S)-адреса, ограничивает размер и число записей; payload рабочего пространства передаёт список клиенту. Редактор задачи работает с динамическими строками ссылок. В карточках переходы являются отдельными ссылками, а не вложенными кнопками. Компактное окно «Итог встречи» собирает четыре значения и отправляет уже существующий `POST /api/key-tasks` с безопасными предустановками.

## Риски

- Ссылки могут вести на внешние системы: открываются только в отдельной вкладке с `noopener`.
- Автоподтягивание суммы и стадии из URL не реализуется без отдельного согласования на чтение CRM; ссылка остаётся достоверной, но не подменяет карточку сделки.
- Новая форма не должна обойти обязательные поля: договорённость формирует описание, а ответственный одновременно назначается исполнителем.
