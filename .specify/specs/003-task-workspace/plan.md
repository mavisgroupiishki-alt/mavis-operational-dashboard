# Технический план: Рабочее пространство задач

**Спека:** [spec.md](spec.md)  **Создан:** 2026-09-25

## Технологии

Существующие FastAPI, Pydantic, SQLite/Supabase KV и статический JavaScript. Новые зависимости не требуются: это сохраняет простую поставку Render и не затрагивает CRM-интеграции.

## Архитектура

```text
Storage KV
  task_workspace_profiles / task_workspace_projects / manual_key_tasks
                    │
FastAPI /api/key-tasks/*
                    │
static app.js: профиль → фильтры → канбан | список | Гант
```

Старое хранилище `manual_key_tasks` остаётся ключом данных. При чтении запись старого формата нормализуется: проект «Без проекта», статус «В работе», один исполнитель, равный ответственному. Это сохраняет уже внесённые задачи без миграции, которая могла бы перезаписать ручные данные.

## Схема данных

- `task_workspace_profiles`: `id`, `name`, `active`, `created_at`, `deleted_at`.
- `task_workspace_projects`: `id`, `name`, `archived`, `created_at`, `archived_at`.
- `manual_key_tasks`: существующие `id`, `title`, `responsible_id`, `deadline`, `priority`, `created_at` плюс `project_id`, `executor_ids`, `status`, `description`, `updated_at`, `created_by_profile_id`, `completed_at`.

Идентификаторы — локальные UUID. Удаление профиля — мягкое; профиль остаётся разрешаемым при выдаче исторических задач. Удаление задачи — явное пользовательское удаление, как в текущем разделе.

## API / Интерфейсы

- `GET /api/key-tasks` — нормализованные задачи, профили, проекты, статусы и метаданные.
- `POST /api/key-tasks` — создание задачи.
- `PATCH /api/key-tasks/{id}` — изменение полей задачи, включая статус.
- `DELETE /api/key-tasks/{id}` — удаление задачи.
- `POST/DELETE /api/key-tasks/profiles` — добавление и мягкое удаление профиля.
- `POST/PATCH /api/key-tasks/projects` — создание и архивирование проекта.
- Старые endpoints команды остаются совместимыми, но интерфейс больше не требует Bitrix-пользователей или ADMIN_KEY для рабочих профилей.

## Зависимости

1. Нормализация данных должна появиться до API.
2. API и тесты должны появиться до смены UI.
3. Интерфейс использует только локальные API раздела.

## Риски

- Старые задачи могли ссылаться на Bitrix ID: нормализация сохраняет их как исторические профили вместо удаления.
- Локальные профили не являются учётными записями: это явно описывается в UI, чтобы не создавать ложного ощущения авторизации.
- На небольшом экране Гант не должен сжимать текст: шкала будет горизонтально прокручиваться, а задачи без срока будут отдельным списком.
